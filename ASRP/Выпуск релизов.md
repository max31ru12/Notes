

Из ветки `develop` создаётся ветка `release`


## Порядок релиза 

### В develop провести тесты и проверки

```bash
poetry run ruff check . 
poetry run pytest 
docker compose -f docker-compose.dev.yml 
config docker compose -f local.yml config
```


### Создать релиз-ветку

```shell
git checkout develop 
git checkout -b release/1.3.0 
git push -u origin release/1.3.0
```

В релиз ветке разрешено только:
- исправление багов
- изменение версии
- документация
- небольшие изменения для релиза

Все найденные баги исправляются в релиз-ветке

### Изменить версию проекта в **poetry** или **npm**

```bash
poetry version 1.0.1

npm version 1.0.1
```


### Создать PR из `release` в `main`

`squash-commit` не использовать, лучше использовать **merge-commit**


###  Поставить тег после мержа в main

```shell
git checkout main 
git pull --ff-only origin main 
git tag -a v1.3.0 -m "Release 1.3.0" 
git push origin v1.3.0
```

####  production deployment

Можно запускать деплой в прод по тэгу

```yml
on:
  push:
    tags:
      - "v*"
```


### Вернуть release изменения в develop

```bash
git merge --no-ff release/1.3.0 
git push origin develop
```
